The problem and the experience

Help at the moment a conversation happens.

Learners need to understand what they heard and know what they can say next—at a café, at work or while travelling.

01

Choose two languages

Select a language you understand and one you are learning. Connect with a host code or your own Google key.

02

Press the big speaking button

See finalized speech, a translation and three suggested replies. Typed phrases work too.

03

Tap, practise and revisit

Tap words for a meaning bubble, switch to pronunciation, hear or copy replies, and reopen saved learning.

Intended benefit: make everyday language practice more accessible through real context. Learning outcomes have not yet been measured.

Context and response generation

Replies follow what is happening now.

A goal is optional. The same Flash request can infer the immediate situation and suggest ways to respond.

Bounded context in each lesson request
1Current utterance and selected language pair
2Up to eight earlier conversation turns
3A scene summary and the previous three suggestions
4Editable learner notes and up to twelve seen words
5An explicit goal or tentative inferred intent

An explicit goal overrides a guess. New conversation clears the scene sent to Google while retaining Saved.

Illustrative scenario

Learner’s goal

“I want vegetarian takeaway.”

A later question

“Will you eat here?”

A context-aware reply could be:
“To take away, please.”

Illustrative scenario. With a blank goal, the model uses the immediate exchange; conversational accuracy needs broader user testing.

Suggestions are kept separate from spoken facts. “Likely you” is a conversational estimate, not verified speaker identity. The learner can confirm “I said this.”

No extra summarization or speaker-classification model call04 / 08

Learning stays local. Live signals stay temporary.

HTTPS, HttpOnly and SameSite=Strict protect browser sessions. Cookie-authenticated writes and WebSocket connections require the app’s own origin.
The server has no transcript/history database. Users must trust the host receiving their key; anyone using the same browser can switch local learner profiles.

Host-code and personal-key users have separate shared model allowances; all personal-key sessions share theirs. Both groups share infrastructure concurrency and pacing limits. The host still pays Cloud Run relay costs.

Quotas are per process and reset after a restart. They are not a hard billing cap. A global AI pause stops paid routes. Scale-to-zero also forgets personal keys, so users may need to reconnect.

Cloud Run + Google AI

Valid personal-key inference, physical-phone capture and broad language/speaker accuracy remain unverified.

Feasible demo today: a framework-free web client and one FastAPI service reuse the existing Google model APIs. There is an Android companion; this PDF focuses on the web flow.
